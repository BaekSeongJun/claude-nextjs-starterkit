## ⚠️ Critical: Next.js 16 Breaking Changes

This project uses **Next.js 16.2.12**, which has significant breaking changes compared to versions 13–15 in your training data. Before writing any code:

1. **Read the Next.js documentation** in `node_modules/next/dist/docs/` — especially:
   - `01-app/01-getting-started/03-layouts-and-pages.md` (core routing concepts)
   - `01-app/01-getting-started/04-linking-and-navigating.md` (Link component, params, searchParams)
   - `01-app/03-api-reference/04-functions/use-params.md` (how params work as Promises in v16)

2. **Key v16 breaking changes:**
   - `params` and `searchParams` are **always Promise** — must use `await` in Server Components or `use()` in Client Components. Synchronous access (v15 compatibility mode) is completely removed.
   - `middleware.ts` is replaced by `proxy.ts` (edge runtime not supported, nodejs only).
   - Parallel Routes slots (`@slot`) require `default.js` (no longer optional).
   - Turbopack is the default bundler (custom webpack setup requires `--webpack` flag).

3. **Heed deprecation notices** in the docs — many image, auth, and config patterns changed in v16.

## Architecture: Layered Component Structure

The codebase follows a **4-layer component hierarchy** + **utilities/validation** layer. This structure determines where new files belong:

### L1: Primitive Components (`components/ui/`)
- **Source:** Generated by `shadcn add` CLI — installed as-is from shadcn/ui registry
- **Rule:** Do not edit directly; CLI updates will overwrite. To customize, wrap in L2 instead.
- **Examples:** `button.tsx`, `input.tsx`, `card.tsx`, `field.tsx` (custom form field API)
- **Key detail:** This project uses `field.tsx` (Field, FieldContent, FieldError, FieldLabel), not shadcn's standard `form.tsx` — see L2 for why.

### L2: Composite Components (`components/forms/`, `components/mode-toggle.tsx`)
- **Purpose:** Combine 2+ Primitives with domain logic
- **Responsibilities:** Form validation (react-hook-form + zod), theme toggle state
- **Example:** `components/forms/login-form.tsx`
  - Imports `@/lib/validations/login` (zod schema)
  - Uses `@/components/ui/field` (not form.tsx) for field layout
  - Wraps with `react-hook-form` for state
  - Calls `onSubmit` handler (stub for backend integration)

### L3: Layout Components (`components/layout/`)
- **Purpose:** Repeated page shell (header, footer, navigation)
- **Files:**
  - `site-header.tsx` — Top bar (logo, nav menu, theme toggle)
  - `site-footer.tsx` — Bottom bar
  - `main-nav.tsx` — Desktop horizontal menu
  - `mobile-nav.tsx` — Mobile slide-out panel (Sheet-based)
  - `nav-items.ts` — Single source of truth for all menu items (add/edit here only)
- **Data flow:** Both `main-nav` and `mobile-nav` consume the same `navItems` array → one change updates desktop + mobile

### L4: Page Components (`app/**/page.tsx`)
- **Purpose:** Map to Next.js routes, compose L3 layout + custom content
- **Current routes:**
  - `/` → `app/page.tsx` (home/introduction)
  - `/login` → `app/(demo)/login/page.tsx` (demo form)
- **Route groups:** `(demo)` folder hides from URL path (URL stays `/login`, not `/demo/login`)

### Utilities & Validation (`lib/`, `lib/validations/`)
- `lib/utils.ts` — `cn()` for classname merging
- `lib/validations/login.ts` — zod schemas (e.g., `loginSchema`)
- Import and use in L2 Composite components

## Key Patterns

### Dark Mode
- **Library:** `next-themes`
- **Implementation:**
  - Wrapper: `ThemeProvider` (`components/theme-provider.tsx`)
  - Root layout (`app/layout.tsx`) wraps with `ThemeProvider`
  - CSS: Tailwind v4 `@custom-variant dark` in `app/globals.css` (sets `.dark` class)
  - Toggle UI: `ModeToggle` component (`components/mode-toggle.tsx`)
- **Adding to pages:** Just include `ModeToggle` in header/layout; `ThemeProvider` handles the rest

### Form Validation (Zod + react-hook-form)
- **Schema definition** (`lib/validations/*.ts`):
  ```ts
  export const loginSchema = z.object({
    email: z.string().email("Invalid email"),
    password: z.string().min(8, "Min 8 chars"),
  })
  export type LoginValues = z.infer<typeof loginSchema>
  ```
- **Form component** (`components/forms/*.tsx`):
  - Import schema + zod type
  - Wrap form in `useForm()` with `zodResolver`
  - Use `Field` + `FieldLabel` + `FieldContent` + `FieldError` from `@/components/ui/field`
  - Reference: `components/forms/login-form.tsx`
- **Backend integration:** Add logic to `onSubmit` handler in form component (currently a stub)

### Navigation
- **Single source of truth:** `components/layout/nav-items.ts` exports `navItems` array
- **Consumed by:** `main-nav.tsx` (desktop) and `mobile-nav.tsx` (mobile)
- **Adding menu items:** Edit `nav-items.ts` → both desktop and mobile automatically update

### Routing
- **App Router** (no Pages Router)
- **Route groups** like `(demo)` don't appear in URL (useful for layout scoping)
- **Dynamic routes** (e.g., `[slug]`): When you add them, remember params are **Promises in v16** — always `await` or `use()` them
- **Current setup:** No dynamic routes yet; all pages are static

### Styling
- **Framework:** Tailwind CSS v4 (CSS-first variant approach)
- **Configuration:** `components.json` (shadcn settings)
  - Style: `radix-nova`
  - Base color: `neutral`
  - Path aliases: `@/components`, `@/lib`, `@/ui`, `@/hooks`
- **Global styles:** `app/globals.css` (CSS variables, dark mode variant)

## Important Caveats

1. **Do not edit `components/ui/` directly**
   - These files are controlled by `shadcn add` CLI
   - Customization must be done in L2 (create a wrapper in `components/forms/` or elsewhere)

2. **Form backend is not wired**
   - `LoginForm.onSubmit()` in `/login` is a stub
   - Add your own API call, auth logic, or server action there

3. **No test framework configured**
   - If you need testing, install and configure Jest or Vitest first
